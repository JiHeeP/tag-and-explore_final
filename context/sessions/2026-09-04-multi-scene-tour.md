# 분석 기록: 장면 여러 개 이어 붙이기 (ThingLink식 투어)

- **일시**: 2026-09-04
- **요구사항 원문**: 장면을 여러 개 이어서 작품을 만들 수 있게 하고 싶다. ThingLink처럼.
- **판정**: ✅ 안전

## 조사 결과

ThingLink는 360 투어에서 "다른 장면으로 이동" 태그(Transit tag / tour tag)로 장면을 연결한다. 편집기에서 이동할 장면을 고르면 학생이 그 태그를 눌렀을 때 다음 장면으로 넘어간다. 이 앱의 기존 구조(배경 1개 + 핫스팟 목록)를 "장면" 단위로 묶고, 핫스팟 콘텐츠 타입에 `장면 이동`을 추가하면 같은 흐름이 된다.

## 영향 범위

| 대상 | 영향 수준 | 상세 |
|---|---|---|
| `supabase/project-scenes.sql` | 낮음 | `projects.scenes jsonb` 컬럼 추가만. 삭제·변경 없음 |
| `source-restored/src/main.jsx` | 높음 | 장면 모델, 편집기 장면 패널, 인스펙터 `장면 이동`, 보기 화면 장면 이동 |
| `source-restored/src/styles.css` | 낮음 | 장면 목록·장면 내비게이션 스타일 |
| 저장 데이터 | 중간 | `scenes` 배열을 새로 저장. 기존 컬럼은 1번 장면을 그대로 미러링 |
| 배포 번들 | 중간 | `recovered-deploy` 번들과 정적 HTML 갱신 |

| 점검 항목 | 결과 | 근거 |
|---|---|---|
| 기존 약속 | ✅ | `/view/:id`, `owner_id` RLS, R2 업로드, Street View 흐름 그대로 유지 |
| 데이터 모양 | ✅ | `scenes`가 없는 옛 행은 장면 1개로 읽힘. 저장 시 옛 컬럼도 함께 채움 |
| 과거 기록 | ✅ | 기존 5개 작품은 수정 없이 열리고, 저장하면 장면 1개짜리로 승격 |
| 사용자 흐름 | ⚠️ | 장면 2개 이상 저장은 SQL 실행 전엔 거부되며 안내 메시지를 띄움 (데이터 유실 방지) |
| 되돌리기 어려움 | ✅ | 컬럼 추가만. 정책·삭제 없음 |

## 구현 내용

| 순서 | 작업 유형 | 대상 | 설명 |
|---|---|---|---|
| 1 | DATABASE_COLUMN | `supabase/project-scenes.sql` | `scenes jsonb` 추가 |
| 2 | DATA_MODEL | `main.jsx` | `normalizeScenes`, `scenesFromRow`, `rowFromProject`, 컬럼 없을 때 폴백 |
| 3 | EDITOR_UI | `main.jsx` 왼쪽 패널 | 장면 목록: 추가·이름 변경·순서 이동·삭제·선택. 장면마다 배경/핫스팟 독립 |
| 4 | INSPECTOR | `main.jsx` | 콘텐츠 타입 `장면 이동` + 이동할 장면 선택. 문 아이콘 자동 지정 |
| 5 | PREVIEW/VIEW | `main.jsx` | 미리보기·보기 화면에서 장면 이동 핫스팟 클릭 시 장면 전환. 장면 칩 내비게이션, `첫 장면` 버튼 |
| 6 | MANAGE | `main.jsx` | 복사 시 장면 id와 연결을 새로 매핑. 홈 카드에 `장면 N개` 표시 |
| 7 | VERIFY | Playwright | 빌드 번들로 보기·편집·저장·폴백 시나리오 자동 확인 |

## 남은 주의사항

- Supabase SQL 편집기에서 `supabase/project-scenes.sql`을 한 번 실행해야 장면 2개 이상이 저장된다.
- 장면 이동 핫스팟은 콘텐츠 창을 열지 않고 바로 이동한다. 설명이 필요하면 텍스트 핫스팟을 따로 둔다.
- 360 배경은 아직 평면 미리보기라, 360 장면 간 이동도 평면 이미지 위에서 동작한다.
